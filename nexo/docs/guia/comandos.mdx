# Comandos

Os comandos permitem que os usuários interajam com seu bot por meio de comandos de barra (`/`) e menus de contexto do Discord. No Nexocord, cada comando é definido em um arquivo e exportado com `default`.

## 🚀 Como funciona

- ⚡ O Nexocord carrega os comandos durante a inicialização do bot.
- 📁 O diretório dos comandos é configurado em `directories.commands`, no arquivo `nexocord.json` ou `nexocord.config`.
- 📦 Cada arquivo de comando deve exportar seu comando com `default`.
- 🗂️ A organização em pastas é livre; o carregador encontra os arquivos recursivamente.

## 🧪 Criando um comando

Neste exemplo, criaremos um comando `/ping` que responde `Pong!`.

<Tabs groupId="command-language">
<TabItem value="ts" label="TypeScript">

```ts title="src/commands/utils/ping.ts"
import { CommandType, createCommand } from "nexocord";

export default createCommand({
  name: "ping",
  description: "Verifica se o bot está online.",
  type: CommandType.ChatInput,
  async run(interaction) {
    await interaction.reply({ content: "Pong!" });
  },
});
```

</TabItem>
<TabItem value="js" label="JavaScript">

```js title="src/commands/utils/ping.js"
const { CommandType, createCommand } = require("nexocord");

module.exports = createCommand({
  name: "ping",
  description: "Verifica se o bot está online.",
  type: CommandType.ChatInput,
  async run(interaction) {
    await interaction.reply({ content: "Pong!" });
  },
});
```

</TabItem>
</Tabs>

O comando precisa estar dentro do diretório configurado em `directories.commands`. Quando o Nexocord inicializar, o carregador encontrará o arquivo e processará sua definição.

## 📋 Propriedades de um comando

| Propriedade | Tipo | Obrigatória | Descrição |
| --- | --- | --- | --- |
| `name` | `string` | Sim | Nome do comando. |
| `description` | `string` | Sim | Descrição exibida pelo Discord. |
| `type` | `CommandType` | Sim | Tipo de comando. |
| `run` | função | Sim | Executa a lógica do comando. |
| `options` | `APIApplicationCommandOption[]` | Não | Parâmetros aceitos pelo comando. |
| `cooldown` | `number` | Não | Intervalo entre usos, em segundos. |
| `autocomplete` | função | Não | Fornece sugestões para opções com autocomplete. |
| `defaultMemberPermission` | `PermissionResolvable \| null` | Não | Permissões exigidas do membro. |
| `botpermission` | chave de `PermissionFlagsBits` | Não | Permissão exigida do bot. |
| `allowIds` | `string[] \| null` | Não | Restringe o uso a IDs permitidos. |
| `dmPermission` | `boolean` | Não | Define se o comando pode ser usado em mensagens diretas. |
| `nsfw` | `boolean` | Não | Restringe o comando a canais NSFW. |

O callback `run` recebe a interação como primeiro argumento. Quando necessário,
você também pode receber o cliente como segundo argumento. Para utilizar
Components V2, receba `{ ui }` como terceiro argumento:

```ts
async run(interaction, client, { ui }) {
  await interaction.reply({
    components: [ui.text("Olá!")],
  });
}
```

Também é possível importar a mesma API diretamente de `nexocord/ui`:

```ts
import { ui } from "nexocord/ui";
```

Nesse caso, não é necessário receber `{ ui }` no callback.

## 🎯 Tipos de comandos

O Nexocord oferece os tipos de comandos do Discord representados por `CommandType`.

<Tabs groupId="command-types">
<TabItem value="chatinput" label="Slash">

```ts
type: CommandType.ChatInput
```

Cria um comando de barra, como `/ping`. É a opção mais comum para comandos com parâmetros e respostas interativas.

</TabItem>
<TabItem value="user" label="User">

```ts
type: CommandType.User
```

Cria uma ação disponível no menu de contexto de um usuário.

</TabItem>
<TabItem value="message" label="Message">

```ts
type: CommandType.Message
```

Cria uma ação disponível no menu de contexto de uma mensagem.

</TabItem>
<TabItem value="primary" label="PrimaryEntryPoint">

```ts
type: CommandType.PrimaryEntryPoint
```

Representa o tipo `PrimaryEntryPoint` disponibilizado pela API. Seu uso depende dos recursos e requisitos específicos do Discord para esse tipo de comando.

</TabItem>
</Tabs>

## 🔐 Permissões e restrições

Você pode definir regras de acesso diretamente na configuração do comando.

- `defaultMemberPermission`: define as permissões necessárias para o membro.
- `botpermission`: define uma permissão necessária para o bot.
- `allowIds`: limita o acesso aos IDs autorizados.
- `dmPermission`: controla a disponibilidade em mensagens diretas.
- `nsfw`: restringe o comando a canais marcados como NSFW.
- `cooldown`: define o intervalo mínimo entre usos, em segundos.

Essas configurações ajudam a controlar a disponibilidade dos comandos. Ainda assim, valide as permissões e os dados recebidos ao executar operações administrativas ou sensíveis.

## 🧩 Opções e autocomplete

As opções permitem receber informações do usuário, como textos, números, usuários e canais. O Nexocord disponibiliza builders por meio de `option`.

Para aprender a declarar parâmetros, configurar limites e implementar sugestões, consulte [Opções de comandos](/docs/options).

## 🗂️ Organização dos arquivos

O carregador percorre recursivamente o diretório configurado em `directories.commands` e considera arquivos `.ts`, `.js`, `.mjs` e `.cjs`. As pastas servem para organização e não alteram o nome do comando.

### 📁 Estrutura de arquivos

Organize os arquivos dentro do diretório configurado em `directories.commands`:

```text
src/
└── commands/
    └── utils/
        └── ban.ts
```

Nesse exemplo, `ban.ts` é um comando independente chamado `/ban`.

### ⚙️ Como funciona

Não há geração automática de subcomandos a partir de pastas na API atual. Declare cada comando exportado diretamente ou use uma configuração compatível com o Discord.js.

## ⚠️ Tratamento de erros

Trate falhas esperadas dentro da função `run`, principalmente ao acessar recursos externos ou executar operações que podem falhar.

Se uma interação já tiver recebido uma resposta, não tente respondê-la novamente. O comportamento de tratamento de erros do framework depende do estado da interação e da implementação do Nexocord.
