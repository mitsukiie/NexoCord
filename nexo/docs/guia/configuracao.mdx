# ⚙️ Configuração

O NexoCord permite personalizar o comportamento do framework por meio de um arquivo de configuração na raiz do projeto.

Você pode utilizar `nexocord.json` ou `nexocord.config`, dependendo do formato de sua preferência.

:::warning
Utilize apenas um arquivo de configuração. Se `nexocord.json` e `nexocord.config` existirem ao mesmo tempo, o NexoCord exibirá um erro.
:::

## 🚀 Criando o arquivo de configuração

### `nexocord.json`

Crie um arquivo chamado `nexocord.json` na raiz do projeto:

```json
{
  "directories": {
    "commands": "./src/commands",
    "events": "./src/events"
  },
  "terminal": {
    "mode": "minimalista",
    "commands": {
      "showFiles": false,
      "showRegistered": true,
      "registeredMessage": "✓ {count} comandos registrados"
    },
    "events": {
      "showFiles": false,
      "showRegistered": true,
      "registeredMessage": "✓ {count} eventos carregados"
    }
  },
  "bot": {
    "cooldown": 3,
    "guildID": [],
    "errors": {
      "interaction": "Ocorreu um erro ao executar este comando."
    }
  }
}
```

### `nexocord.config`

Se preferir um formato de configuração baseado em chaves e valores, utilize `nexocord.config`:

```properties
# Diretórios
DIRECTORIES_COMMANDS=./src/commands
DIRECTORIES_EVENTS=./src/events

# Terminal
TERMINAL_MODE=minimalista
TERMINAL_COMMANDS_SHOW_FILES=false
TERMINAL_COMMANDS_SHOW_REGISTERED=true
TERMINAL_COMMANDS_REGISTERED_MESSAGE="✓ {count} comandos registrados"
TERMINAL_EVENTS_SHOW_FILES=false
TERMINAL_EVENTS_SHOW_REGISTERED=true
TERMINAL_EVENTS_REGISTERED_MESSAGE="✓ {count} eventos carregados"

# Bot
BOT_COOLDOWN=3
BOT_GUILD_ID=[]
BOT_ERRORS_INTERACTION="Ocorreu um erro ao executar este comando."
```

Os dois formatos permitem configurar as mesmas opções. Escolha aquele que preferir.

## 📂 Diretórios

A propriedade `directories` define onde o NexoCord procura os arquivos de comandos e eventos.

| Propriedade | Tipo | Descrição |
|---|---|---|
| `directories.commands` | `string` | Caminho da pasta de comandos. |
| `directories.events` | `string` | Caminho da pasta de eventos. |

Exemplo:

```json
{
  "directories": {
    "commands": "./src/commands",
    "events": "./src/events"
  }
}
```

Os caminhos devem corresponder à estrutura do seu projeto.

## 🖥️ Terminal

A propriedade `terminal` controla as informações exibidas durante a inicialização do framework.

| Propriedade | Tipo | Descrição |
|---|---|---|
| `terminal.mode` | `"informativo" \| "minimalista"` | Define o formato dos logs. |
| `terminal.commands.showFiles` | `boolean` | Exibe os arquivos de comandos encontrados. |
| `terminal.commands.showRegistered` | `boolean` | Exibe a mensagem de registro dos comandos. |
| `terminal.commands.registeredMessage` | `string` | Personaliza a mensagem de registro dos comandos. |
| `terminal.events.showFiles` | `boolean` | Exibe os arquivos de eventos encontrados. |
| `terminal.events.showRegistered` | `boolean` | Exibe a mensagem de carregamento dos eventos. |
| `terminal.events.registeredMessage` | `string` | Personaliza a mensagem de carregamento dos eventos. |

### Modos de exibição

- `informativo`: exibe informações adicionais nos logs, como nível e horário.
- `minimalista`: mantém a saída do terminal mais simples.

### Personalizando mensagens

As mensagens de registro aceitam o marcador `{count}`, substituído pela quantidade correspondente de comandos ou eventos.

Exemplo:

```json
{
  "terminal": {
    "commands": {
      "registeredMessage": "✓ {count} comandos registrados com sucesso"
    },
    "events": {
      "registeredMessage": "✓ {count} eventos carregados com sucesso"
    }
  }
}
```

## 🤖 Bot

A propriedade `bot` reúne configurações relacionadas ao comportamento do bot.

| Propriedade | Tipo | Descrição |
|---|---|---|
| `bot.cooldown` | `number` | Cooldown padrão dos comandos, em segundos. |
| `bot.guildID` | `string[]` | Lista de IDs de servidores utilizada pelo framework quando aplicável. |
| `bot.errors.interaction` | `string` | Mensagem exibida quando ocorre um erro durante a execução de uma interação. |

### Cooldown padrão

O cooldown define o tempo de espera padrão entre execuções de um comando, conforme o comportamento implementado pelo framework.

```json
{
  "bot": {
    "cooldown": 5
  }
}
```

Nesse exemplo, o cooldown padrão é de cinco segundos. Caso o comando permita configurar seu próprio cooldown, o valor específico do comando pode prevalecer sobre o padrão global.

### Mensagem de erro

Você pode personalizar a mensagem exibida quando uma interação falha:

```json
{
  "bot": {
    "errors": {
      "interaction": "Não foi possível executar esta interação."
    }
  }
}
```

## 🔑 Inicializando o bot

O arquivo de configuração não substitui as opções de inicialização do bot. O token, as intents e outras opções suportadas continuam sendo informados em `Bootstrap.init()`.

```ts
import { Bootstrap } from "nexocord";
import { GatewayIntentBits } from "discord.js";

await Bootstrap.init({
  token: process.env.TOKEN,
  intents: [GatewayIntentBits.Guilds]
});
```

O NexoCord carrega automaticamente o arquivo de configuração encontrado na raiz do projeto.

:::tip
Mantenha o token em uma variável de ambiente, como `TOKEN`, e nunca o publique no repositório.
:::

## 🧩 Configurações personalizadas da aplicação

Se precisar armazenar valores específicos do seu bot, você pode passá-los pela propriedade `settings` de `Bootstrap.init()`.

```ts
import { Bootstrap } from "nexocord";
import { GatewayIntentBits } from "discord.js";

await Bootstrap.init({
  token: process.env.TOKEN,
  intents: [GatewayIntentBits.Guilds],
  settings: {
    projectName: "Meu Bot",
    supportServer: "https://discord.gg/seu-servidor",
    welcomeChannelId: "123456789012345678"
  }
});
```

Esses valores pertencem à sua aplicação, não à configuração interna do NexoCord.

Consulte a documentação da API para saber como acessar `settings` durante a execução do bot.

## ✅ Boas práticas

- Mantenha apenas um arquivo de configuração na raiz do projeto.
- Utilize `nexocord.json` se preferir uma estrutura organizada em JSON.
- Armazene segredos, como o token do bot, em variáveis de ambiente.
- Utilize `settings` para dados personalizados da aplicação.
- Mantenha os diretórios configurados de acordo com a estrutura do projeto.
