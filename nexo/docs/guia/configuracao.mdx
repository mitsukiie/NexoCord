# ⚙️ Configuração (settings)

No Nexo, você configura os comportamentos globais do framework usando a propriedade `settings` do `Bootstrap.init()`.

As configurações permitem controlar os logs do terminal, definir o cooldown padrão dos comandos e armazenar valores personalizados da sua aplicação.

:::info
Nesta página, `paths.commands` e `paths.events` são utilizados como exemplos. Você pode organizar seus arquivos em qualquer estrutura de pastas, desde que configure os caminhos corretamente.
:::

## 🚀 Como configurar

Você pode definir as configurações de duas formas:

1. **Inline:** diretamente no `Bootstrap.init()`, ideal para projetos pequenos.
2. **Em um arquivo separado:** usando `settings.ts` ou `settings.js`, recomendado para projetos médios e grandes.

## 🧩 Configuração inline

<Tabs groupId="lang-settings-inline">
<TabItem value="js" label="JavaScript">

```js
const { Bootstrap } = require('nexocord');
const { GatewayIntentBits } = require('discord.js');

async function main() {
  await Bootstrap.init({
    token: process.env.DISCORD_TOKEN,
    intents: [GatewayIntentBits.Guilds],
    paths: {
      commands: 'src/commands',
      events: 'src/events',
    },
    settings: {
      terminal: {
        mode: 'minimalista',
        showSlashCommandsRegistred: true,
      },
      bot: {
        cooldown: 5,
      },
      custom: {
        projectName: 'Meu Bot',
      },
    },
  });
}

main();
```

## 📂 Arquivo separado

Em projetos maiores, separar as configurações ajuda a manter o arquivo de inicialização organizado.

Estrutura sugerida:

```text
src/
├── index.ts
└── settings.ts
```

## 🧠 Valores padrão

O Nexo permite fornecer apenas as configurações que você deseja personalizar por meio de `PartialSettings`.

Por exemplo, você pode definir apenas o cooldown:

```ts
await Bootstrap.init({
  settings: {
    bot: {
      cooldown: 5,
    },
  },
});
```

Os demais valores dependem dos padrões definidos pela implementação de `setGlobalSettings()`.

:::warning
Confira se os padrões estão configurados corretamente no framework. O `Bootstrap.init()` recebe as configurações parciais, mas é `setGlobalSettings()` quem determina como elas são armazenadas e combinadas com os valores padrão.
:::

## 📋 Opções disponíveis

### 🖥️ `terminal`

Controla as informações exibidas no terminal.

| Propriedade | Tipo | Descrição |
| --- | --- | --- |
| `mode` | `'informativo' \| 'minimalista'` | Define o modo de exibição dos logs. |
| `showSlashCommandsFiles` | `boolean` | Exibe os arquivos de comandos encontrados durante o carregamento. |
| `showSlashCommandsRegistred` | `boolean` | Exibe informações sobre os comandos registrados no Discord. |
| `showEventsFiles` | `boolean` | Exibe os arquivos de eventos encontrados. |
| `showEventsRegistred` | `boolean` | Exibe informações sobre os eventos registrados no cliente. |

### 🤖 `bot`

Define configurações globais relacionadas aos comandos e servidores.

| Propriedade | Tipo | Descrição |
| --- | --- | --- |
| `cooldown` | `number` | Cooldown padrão dos comandos, em segundos. |
| `guildID` | `string[]` | Lista de IDs de servidores utilizada pelo framework quando aplicável ao registro ou à sincronização de comandos. |

### 🧩 `custom`

Permite armazenar configurações específicas da sua aplicação sem precisar adicioná-las às opções internas do Nexo.

O tipo é `Record<string, any>`.

```ts
custom: {
  projectName: 'Meu Bot',
  supportServer: 'https://discord.gg/seu-servidor',
  welcomeChannelId: '123456789012345678',
}
```

Você pode acessar esses valores por meio do mecanismo de configurações disponibilizado pelo framework.

:::tip
Use `custom` para valores próprios do seu projeto, como IDs de canais, IDs de cargos, URLs e opções específicas da aplicação.
:::

## ✅ Boas práticas

- 🗂️ Separe as configurações em um arquivo próprio quando o projeto crescer.
- 🔐 Armazene o token em uma variável de ambiente e nunca o publique no repositório.
- 🧩 Utilize `custom` para configurações específicas da sua aplicação.
- 🎯 Personalize somente as opções necessárias.
- 🧼 Mantenha as configurações declarativas, sem colocar a lógica de negócio dentro delas.
