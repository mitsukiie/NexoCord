# 📌 Responders

Os **responders** permitem tratar interações com componentes do Discord, como botões, menus de seleção e modais, sem precisar concentrar toda a lógica no comando que criou o componente.

Com `createResponder()`, você define uma rota usando `customId` e escolhe os tipos de interação que ela pode receber.

## 🚀 Como funciona

- 🎯 `customId` identifica a rota do responder.
- 🧩 Parâmetros como `:id` permitem criar rotas dinâmicas.
- ⚙️ `type` define quais tipos de interação serão aceitos.
- 🏃 `run` é executado quando uma interação corresponde à rota.
- 🔐 `parse`, `lifetime`, `expire` e `cache` permitem configurar validação e comportamento.

## 🧪 Exemplo básico

O exemplo abaixo cria um responder para um botão com o identificador `user/button`.

```ts
import { createResponder, ResponderType } from "nexocord";

export default createResponder({
  customId: "user/button",
  type: ResponderType.Button,

  async run(interaction) {
    await interaction.reply({
      content: "Botão clicado!",
    });
  },
});
```

O componente que dispara o responder deve usar o mesmo `customId`:

```ts
import {
  ActionRowBuilder,
  ButtonBuilder,
  ButtonStyle,
} from "nexocord";

const row = new ActionRowBuilder<ButtonBuilder>().addComponents(
  new ButtonBuilder()
    .setCustomId("user/button")
    .setLabel("Clicar")
    .setStyle(ButtonStyle.Success),
);
```

O exemplo do componente mostra apenas a criação do botão. Você ainda precisa enviar a `row` em uma mensagem ou resposta de interação.

## 📂 Carregamento dos responders

:::warning Importante
Os responders não são carregados automaticamente apenas por estarem em um arquivo. O arquivo precisa ser importado por algum ponto da aplicação para que `createResponder()` seja executado e registre a rota.
:::

Declare o responder fora de `run` ou de outros handlers que possam ser executados repetidamente. Assim, você evita registrar a mesma rota várias vezes.

## 🧩 Parâmetros na rota

Você pode definir parâmetros dinâmicos no `customId` usando `:` seguido do nome do parâmetro.

```ts
import { createResponder, ResponderType } from "nexocord";

export default createResponder({
  customId: "user/:id",
  type: ResponderType.Button,

  async run(interaction, { id }) {
    await interaction.reply({
      content: `Identificador recebido: ${id}`,
    });
  },
});
```

Se o componente usar `customId: "user/123"`, o parâmetro `id` será `"123"`.

Você também pode utilizar vários parâmetros:

```ts
customId: "user/:id/action/:action"
```

Nesse caso, os valores serão disponibilizados em `params`, de acordo com os nomes definidos na rota.

Por padrão, os parâmetros extraídos são strings.

## 📋 Campos do responder

| Campo | Tipo | Obrigatório | Descrição |
| --- | --- | --- | --- |
| `customId` | `string` | Sim | Padrão usado para identificar a rota da interação. |
| `type` | `ResponderType \| ResponderType[]` | Sim | Tipo ou tipos de interação aceitos. |
| `run` | `function` | Sim | Função executada quando a rota corresponde à interação. |
| `parse` | `ZodTypeAny \| (params) => any` | Não | Schema ou função para validar ou transformar os parâmetros. |
| `lifetime` | `'once' \| 'temporary'` | Não | Define uma restrição de uso para o responder. |
| `expire` | `number` | Não* | Tempo de expiração em milissegundos, conforme o modo de vida configurado. |
| `cache` | `'cached' \| 'guild'` | Não | Restringe o contexto em que a interação pode ser processada. |

\* `expire` é obrigatório quando `lifetime` é `'temporary'`, conforme as regras do Nexocord.

Você também pode aceitar mais de um tipo no mesmo responder:

```ts
type: [ResponderType.Button, ResponderType.SelectString]
```

Como o tipo de `interaction` será uma união, verifique qual interação foi recebida antes de acessar propriedades específicas:

```ts
import { createResponder, ResponderType } from "nexocord";

export default createResponder({
  customId: "user/action",
  type: [ResponderType.Button, ResponderType.SelectString],

  async run(interaction) {
    if (interaction.isButton()) {
      await interaction.reply("Botão clicado!");
      return;
    }

    if (interaction.isStringSelectMenu()) {
      await interaction.reply(
        `Opção selecionada: ${interaction.values.join(", ")}`,
      );
    }
  },
});
```

## 🧠 Validando parâmetros com `parse`

A propriedade `parse` permite validar ou transformar os parâmetros extraídos do `customId`.

Você pode fornecer um schema do Zod ou uma função própria, conforme os tipos aceitos pelo Nexocord.

```ts
parse: (params) => ({
  id: Number(params.id),
})
```

Nesse exemplo, `id` é convertido de string para número. Em rotas que recebem dados externos, valide também se a conversão produziu um valor válido.

## ⏱️ Lifetime e expiração

O campo `lifetime` configura a duração ou a quantidade de usos permitidos para o responder.

### `lifetime: 'once'`

```ts
lifetime: "once"
```

Use quando o responder deve ser utilizado uma única vez, conforme a semântica implementada pelo Nexocord.

### `lifetime: 'temporary'`

```ts
lifetime: "temporary",
expire: 15_000
```

Use quando o responder deve expirar após um período limitado. Nesse exemplo, o tempo configurado é de 15 segundos.

## 🔐 Cache e contexto

O campo `cache` permite restringir o contexto em que a interação será processada.

- `cache: 'guild'`: exige um contexto de servidor.
- `cache: 'cached'`: exige que o servidor esteja em cache.

Quando o contexto não atende à restrição, o Nexocord pode responder automaticamente com uma mensagem efêmera, conforme o comportamento da implementação.

## ✅ Boas práticas

- 🧱 Organize os `customId` com padrões consistentes, como `user/:id/action`.
- 🧪 Valide os parâmetros recebidos em rotas importantes.
- 🔁 Registre os responders uma única vez durante a inicialização.
- ⏳ Utilize expiração quando uma interação precisar ficar disponível por tempo limitado.
- 🧼 Mantenha a lógica de cada interação separada para facilitar a manutenção.
