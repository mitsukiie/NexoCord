# 🧩 Migração

Esta página destaca as mudanças relevantes para projetos que estão usando
exemplos ou APIs anteriores do NexoCord.

## Assinatura atual de `run`

A API atual não usa um objeto `ctx`. O callback de um comando recebe a
interação estendida, o cliente e as dependências:

```ts
import { CommandType, createCommand } from "nexocord";

export default createCommand({
  name: "ping",
  description: "Responde com pong.",
  type: CommandType.ChatInput,
  async run(interaction) {
    await interaction.reply({ content: "Pong!" });
  },
});
```

Substitua usos antigos:

| API antiga | API atual |
| --- | --- |
| `ctx.interaction` | `interaction` |
| `ctx.client` | `client` |
| `ctx.reply(...)` | `interaction.reply(...)` |
| `ctx.followUp(...)` | `interaction.followUp(...)` |

`interaction` continua oferecendo os métodos e propriedades do Discord.js e
também aceita componentes declarativos quando a API `ui` é injetada no callback
ou importada de `nexocord/ui`.

## Configuração da versão atual

A configuração do framework fica na raiz do projeto em `nexocord.json` ou
`nexocord.config`, mas nunca nos dois ao mesmo tempo:

```json
{
  "directories": {
    "commands": "src/commands",
    "events": "src/events"
  },
  "terminal": {
    "mode": "minimalista"
  },
  "bot": {
    "cooldown": 3
  }
}
```

As opções antigas de caminhos e terminal devem ser convertidas para
`directories`, `terminal.commands` e `terminal.events`. Consulte
[Configuração](/docs/configuration) para a lista completa.

## Components V2

Respostas com Components V2 usam `components` na interação atual:

```ts
async run(interaction, client, { ui }) {
  await interaction.reply({
    components: [
      ui.container(
        ui.text("Olá!"),
      ),
    ],
  });
}
```

Fora do callback, ou quando preferir importar explicitamente, use:

```ts
import { ui } from "nexocord/ui";
```

A API importada e a API recebida em `{ ui }` são equivalentes.

Não combine Components V2 com `content` ou `embeds` na mesma resposta. Para
respostas tradicionais, continue usando `interaction.reply({ content })`.

## Responders

Responders atuais são registrados por `createResponder()` quando o módulo é
importado. Eles usam `customId`, `type` e um callback `run`:

```ts
import { createResponder, ResponderType } from "nexocord";

export default createResponder({
  customId: "ticket/:id",
  type: ResponderType.Button,
  run(interaction, { id }) {
    return interaction.reply({ content: `Ticket: ${id}` });
  },
});
```

Garanta que o módulo do responder seja importado durante a inicialização.
